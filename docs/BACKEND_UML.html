SECTION 03

Return Stage Pipeline (State Machine)

Every client progresses through 7 linear stages. Any stage can branch to extended. Backward transitions are restricted.

Return Stage State Machine
%%{init: {'theme': 'dark'}}%% stateDiagram-v2 [*] --> new_intake : Client signs up new_intake --> collecting_docs : Intake submitted collecting_docs --> ready_to_prep : All docs received ready_to_prep --> in_preparation : Preparer accepts in_preparation --> client_review : Return completed client_review --> pay_and_sign : Client approves pay_and_sign --> filed : Payment + signature done new_intake --> extended : Extension needed collecting_docs --> extended : Extension needed ready_to_prep --> extended : Extension needed in_preparation --> extended : Extension needed client_review --> extended : Extension needed extended --> collecting_docs : Resume after extension filed --> [*]

Stage Transition Rules

FromToTriggerRequirements
new_intakecollecting_docsIntake form submittedAll required intake fields complete
collecting_docsready_to_prepAll checklist items receiveddocumentsSubmitted >= documentsRequired
ready_to_prepin_preparationPreparer clicks "Accept Case"Preparer assigned, deposit paid
in_preparationclient_reviewReturn sent to clientReturn PDF uploaded, returnSentDate set
client_reviewpay_and_signClient approves returnClient reviews and confirms
pay_and_signfiledPayment received + signedInvoice paid, 8879 signed, 7216 consent
Any pre-filedextendedExtension filedExtension reason provided, Form 4868 generated

Non-negotiable safety rule: AI output NEVER touches production data directly. All AI results go to quarantine tables with status: 'pending_review'. A human must approve before data is promoted.

Compliance Requirements

RegulationRequirementImplementation
IRC 7216 Written consent before disclosing tax return information Digital 7216 consent form with signature capture. Stored in signatureState. Cannot proceed to filing without consent.

SECTION 14

Business Rules & Constraints

AI Safety (Non-negotiable)

Quarantine Pattern: Every AI-generated output is written to its respective table with status: 'pending_review'. The preparer dashboard displays these with distinct quarantine styling. Only after explicit human approval does the mutation intelligence.approve(id) promote the record to status: 'approved'. Rejected records get status: 'rejected' and are archived, never deleted.
  • 8 entity types are quarantined (see Section 4)
  • AI draft messages are shown as suggestions, never sent automatically
  • Confidence scores are displayed alongside every extraction
  • Audit log records every approve/reject decision with actor and timestamp

Payment Before Signature

Sequence constraint: Client must complete payment (Invoice status = paid) before the 8879 e-file signature authorization is presented. This ensures preparer compensation before filing.

Compliance Rules

RuleEnforcement
IRC 7216 consent required Cannot advance to filed without signed 7216 consent. sign7216() must be called and recorded with timestamp before advanceStage(filed) is allowed.
Form 8867 due diligence If return claims EITC, CTC, AOTC, or HOH, smart checklist auto-generates 8867 questions. Preparer must answer all before stage can advance past in_preparation.
Form 8879 signature ERO PIN must be verified. Digital signature captured with timestamp and IP. Both client and preparer signatures required. ERO settings page manages preparer PIN.
Circular 230 compliance All preparer actions are audit-logged. AI compliance alerts reference specific Circular 230 sections. Written advice is flagged for documentation requirements.

Stage Transition Constraints

  • Stages can only advance forward (no backward transitions except via extension branch)
  • collecting_docs → ready_to_prep: documentsSubmitted must equal documentsRequired
  • ready_to_prep → in_preparation: depositPaid must be true
  • pay_and_sign → filed: invoice paid AND 8879 signed AND 7216 consented
  • Extension branch is available from any pre-filed stage; requires extensionReason

Escalation Timing

  • Escalation cron runs daily, checks lastActivity against thresholds
  • Day 3: Level 1 (reminder) — AI drafts a gentle portal nudge
  • Day 7: Level 2 (urgent) — Priority badge elevated, email notification
  • Day 10: Level 3 (schedule_call) — Suggest phone outreach, auto-pick time slot
  • Day 14: Level 4 (final_notice) — Preparer alerted, case flagged in dashboard
  • Any client activity resets the escalation timer to zero

Data Integrity

  • Soft deletes only — no hard deletes on any entity for audit compliance
  • All monetary values stored in cents (integer) to avoid floating-point errors
  • Timestamps stored as Unix milliseconds (Convex standard)
  • Client email must be unique (indexed)
  • Document storageIds must reference valid Convex file storage entries
