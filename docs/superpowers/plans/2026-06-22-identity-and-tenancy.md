# ① Identity & Tenancy — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real auth + database-enforced multi-tenant isolation, so every later slice can assume an authenticated user scoped to exactly one firm.

**Architecture:** Supabase Postgres with Row-Level Security keyed on `firm_id` (the isolation floor). Firms/preparers authenticate through Clerk Organizations; clients through Supabase OTP. Both mint JWTs whose claims (`firm_id`, `role`, `user_type`, `client_id`) RLS reads via `auth.jwt()`. A repository/service layer in the Next.js app re-checks authorization (defense in depth) and writes an append-only `audit_log` on every mutation. Built in an isolated `backend` worktree so the live mockup is untouched.

**Tech Stack:** Next.js 16 (existing app), Supabase (Postgres + Auth), Drizzle ORM + drizzle-kit, `postgres` (postgres-js) client, `@clerk/nextjs`, `svix` (Clerk webhook verification), Zod, Vitest (new), Supabase CLI (local stack for tests).

## Global Constraints

- TypeScript everywhere; Node 20+.
- **RLS is mandatory on every table** — no table ships without `enable row level security` + a `firm_id` policy. A table with RLS disabled is a plan failure.
- Every mutation writes one `audit_log` row (actor, action, resource, firm_id). No raw PII (SSN/bank) in `audit_log.metadata` or any log.
- `firm_id uuid not null` on every tenant table.
- All work on branch `backend` in worktree `/Users/davidkim/Desktop/docket-backend`. Do NOT push to `petal` or deploy to production from this plan.
- No secrets in code or git — only `.env.local` (gitignored) and `.env.example` (committed, values blank).

```ts
import { drizzle } from "drizzle-orm/postgres-js";
import postgres from "postgres";
import * as schema from "./schema";
const url = process.env.DATABASE_URL!;
// service connection (RLS-bypassing; only trusted, manually-scoped server code)
export const db = drizzle(postgres(url, { prepare: false }), { schema });
// tenant connection: runs each query with the user's JWT claims so RLS applies
export function tenantDb(claims: Record<string, unknown>) {
  const sql = postgres(url, { prepare: false });
  return {
    async run<T>(fn: (tx: ReturnType<typeof drizzle>) => Promise<T>): Promise<T> {
      return sql.begin(async (tx) => {
        await tx`select set_config('role','authenticated',true)`;
        await tx`select set_config('request.jwt.claims', ${JSON.stringify(claims)}, true)`;
        return fn(drizzle(tx as any, { schema }));
      });
    },
  };
}
```

```sql
-- helper: current firm from JWT
create or replace function auth.firm_id() returns uuid language sql stable as
  $$ select nullif(current_setting('request.jwt.claims', true)::json ->> 'firm_id','')::uuid $$;
create or replace function auth.role_claim() returns text language sql stable as
  $$ select current_setting('request.jwt.claims', true)::json ->> 'role' $$;

-- firms: readable by members of that firm; writable by owner/admin
create policy firms_read on firms for select using (id = auth.firm_id());
create policy firms_write on firms for all using (id = auth.firm_id() and auth.role_claim() in ('owner','admin'))
  with check (id = auth.firm_id());

-- firm_members / clients / audit_log: scoped by firm_id; writes gated as noted in the spec
create policy members_rw on firm_members for all using (firm_id = auth.firm_id()) with check (firm_id = auth.firm_id());
create policy clients_rw on clients for all using (firm_id = auth.firm_id()) with check (firm_id = auth.firm_id());
create policy audit_read on audit_log for select using (firm_id = auth.firm_id());
create policy audit_insert on audit_log for insert with check (firm_id = auth.firm_id());
```
Apply: `npx supabase migration up` (or `psql $DATABASE_URL -f supabase/migrations/0001_rls.sql`).
